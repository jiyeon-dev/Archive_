# 1장 리액트는 진화 중이다

## 핵심 요약

-

## 1.1 리액트란 무엇인가

- 리액트의 5가지 핵심 특징
  - 재사용과 합성이 가능한 컴포넌트로부터 UI를 만든다.
  - JSX(HTML 스타일의 템플릿과 자바스크립트를 결합한 요소)를 사용해 UI를 기술한다.
  - 관용적 제약을 너무 많이 도입하지 않으면서도 자바스크립트를 최대한 활용한다.
  - 상태와 UI를 지능적으로 동기화한다.
  - 코드, 애셋, 데이터를 읽어오는 방법과 시간을 관리하도록 돕는다.

### 1.1.1 컴포넌트에서 UI 만들기

- JSX를 통해 컴포넌트를 만들면 캡슐화, 재사용, 합성 등을 쉽게 할 수 있다.

### 1.1.2 상태와 UI의 동기화

- `state`: 앱이 특정 시점에 보유한 데이터.
- 리액트는 컴포넌트의 상태에 반응해서 인터페이스를 재렌더링(re-rendering)한다.

### 1.1.3 컴포넌트 유형 이해하기

| 컴포넌트 유형 | 설명 |
| --- | --- |
| 함수 컴포넌트 | 프로퍼티를 전달받고 훅을 사용해 상태를 관리하고 부수 효과를 수행하며, UI를 반환하는 자바스크립트 함수 |
| 클래스 컴포넌트 | UI를 반환하는 render 메서드가 포함된 자바스크립트 클래스. 생성자 함수 안에서 상태를 설정할 수도 있고, 생명 주기 메서드 안에서 상태를 관리하거나 부수 효과를 수행할 수도 있음 |

- 예전에는 상태를 가지고 부수 효과를 일으키는 컴포넌트를 만들 때 클래스 컴포넌트가 유일한 방법이었으나, 훅이 생기면서 함수 컴포넌트에서도 가능해졌다.

## 1.2 리액트의 새 기능

- `use`로 시작하는 단어들(`useState`, `useReducer`, `useContext`, `useEffect`, `useTransition`)은 *리액트 훅*이다.
- 함수 컴포넌트에 상태, 생명 주기, 컨텍스트 등을 다룰 수 있는 훅을 제공한다.
- 훅을 통해 함수 컴포넌트에 상태를 추가하고, 부수 효과를 캡슐화하고, 코드를 재사용할 수 있다.
- 현재도 계속해서 다양한 훅이 개발되고 있다.

## 1.3 리액트 훅은 함수 컴포넌트에 상태를 추가할 수 있다

### 1.3.1 상태가 있는 함수 컴포넌트: 코드를 더 적게 작성하고, 더 잘 조직화하자

- 함수 컴포넌트의 장점 (클래스 컴포넌트보다 좋은 점)
  - 코드 양이 적다.
  - 관련 코드를 함께 유지하면서 정리할 수 있기 때문에 코드를 더 잘 조직할 수 있다.
  - 기능을 외부 함수로 추출해서 공유하고 재사용할 수 있다.
  - 더 쉽게 컴포넌트를 테스트할 수 있다.
  - 클래스 생성자에서 `super()`를 호출할 필요가 없다.
  - `this`를 다루거나 핸들러를 바인딩할 필요가 없다.
  - 생명 주기 모델이 더 단순하다.
  - 상태가 핸들러, 부수 효과 함수, 반환된 UI 등의 영역 안에 지역적으로 존재한다.

### 1.3.2 커스텀 훅: 더 쉬운 코드 재사용

- 커스텀 훅을 만들면 조직화를 한 단계 더 진행해 기능을 외부 함수로 분리할 수 있다.
- 커스텀 훅은 자기 목적에 맞게 자신만의 상태를 유지할 수 있고, 사용할 때는 이를 반환해야 한다.

### 1.3.3 이미 만들어진, 잘 테스트된 기능을 제공하는 서드파티 훅들

- 대표적인 서드파티 훅/라이브러리
  - 리액트 라우터(React Router): 앱 내 페이지 이동과 URL 상태 관리를 도와주는 컴포넌트와 훅을 제공한다.
  - 리액트 리덕스(React Redux): Redux 저장소와 리액트 컴포넌트를 연결하는 훅을 제공한다.
  - 리액트 스프링(React Spring): 스프링 기반 애니메이션을 구현할 수 있는 훅을 제공한다.

## 1.4 동시 렌더링과 Suspense를 통한 더 나은 UX

- 동시 렌더링과 Suspense는 오래 걸리는 렌더링이나 데이터 로딩 중에도 더 나은 사용자 경험을 제공하기 위한 기능이다.

### 1.4.1 동시 렌더링

- 동시 렌더링(concurrent rendering)은 렌더링 작업을 더 작은 단위로 나누고, 필요하면 작업을 잠시 중단하거나 재개할 수 있게 하는 방식이다.
- 상태 변경에 맞게 DOM을 갱신하는 작업을 조율해서 사용자와의 상호작용에 더 잘 응답할 수 있게 한다.
- 리액트 아키텍처는 작업을 더 작은 단위로 나누고, 리액트 스케줄러는 각 작업 단위의 우선순위에 따라 어떤 작업을 실행할지 결정한다.
- 우선순위가 높은 업데이트가 먼저 처리될 수 있도록 돕는다.
- 예: `useTransition`, `useDeferredValue`

### 1.4.2 Suspense

- `Suspense` 컴포넌트는 하위 컴포넌트가 아직 렌더링 준비를 마치지 못했을 때 폴백(fallback) 콘텐츠를 보여줄 수 있게 한다.
- UI 일부를 `Suspense`로 감싸고 `fallback` 프로퍼티를 이용해 일시 중단되었을 때 어떤 콘텐츠를 표시할지 지정할 수 있다.
- 예를 들어, 코드 분할로 컴포넌트를 불러오거나 Suspense를 지원하는 데이터 로딩 도구를 사용할 때 로딩 UI를 표시할 수 있다.

  ```jsx
  <Suspense fallback={<Spinner />}><MyComponent /></Suspense>
  ```
